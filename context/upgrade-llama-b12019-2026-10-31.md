# llama.cpp upgrade brief: b11118 → b12019 (2026-10-31)

Survey of the 902 commits between `b11118` (e6ab7c1a, last upgrade, part 14) and
`b12020` (latest; we pin `b12019`, the latest with a published immutable tag).
Our model is the Qwen3.8-27B hybrid (GatedDeltaNet recurrent + sparse attention +
MTP head; `qwen3next`/`qwen4exp` in the tree), run with `-fa on -ctk/-ctv q8_0
-kvu --cache-reuse --ctx-checkpoints 4 --spec-type ngram-map-k,draft-mtp`.

**Verdict: upgrade — but it is NOT output-identical. Re-baseline greedy and
tool-calling after.** The range carries fixes aimed straight at our config
(hybrid slot-restore, MTP checkpoint bloat, recurrent-state cleanup) alongside
output-changing sampling/FA/parser changes. No requant required. Two unrelated
risks (#29172, #25618) are still open at b12019.

## Not a blocker for us (verified against docker-compose.yml)

- **#30159 default port 8080→9931:** we pass `--port 8080` explicitly, so
  networking is unaffected.
- **#31242 `--model` now required:** we pass `-m /models/...`, so fine.
- No flag we pass was removed or renamed (`-fa`, `-ctk/-ctv`, `-kvu`,
  `--cache-reuse`, `--ctx-checkpoints`, `-ngl`, `--jinja`, `--spec-type`,
  `--spec-draft-n-max/-n-min/-p-min`, `ngram-map-k`/`draft-mtp` all confirmed
  present upstream). The server will start on b12019.

## The wins (directly our config)

- **#26004 preserves context checkpoints across slot save/restore — this fixes
  llama.cpp#28194**, the hybrid/recurrent slot-restore that reused ZERO tokens
  and forced a full re-prefill. Its PR names Qwen3-Next explicitly. This is the
  "resume without re-prefill" capability OPEN-WORK/HANDOFF flagged borrowing from
  llamAmpere/Strata — mainline now has it. Re-verify it actually rolls back.
- **#30514 honor PARTIAL_ONLY in plain KV cache** — PR body cites "Qwen3.8-27B
  with draft-mtp ... MTP head puts its whole KV into every checkpoint ...
  ~1.2 GiB/checkpoint at 262k." Cuts our `CTX_CHECKPOINTS=4` + `draft-mtp` VRAM.
- Hybrid/recurrent/MTP correctness + robustness: #27530 (stale K/V+recurrent
  state after failed restore), #30020 (MTP spec-init realloc crash), #29856
  (recurrent reserve), #29019 (spec batch/token order), #30574 (draft state in
  slot file), #29172-adjacent graph fixes.
- New additive `--spec-draft-n-ubatch` (#30459, credited to Qwen3.8-Flash-Next)
  frees draft VRAM for target KV. Worth adopting after the baseline settles.

## Output-changing — must re-baseline (greedy, temp 0)

- **#29797** greedy selection for temp-0 chains — changes temp-0 output; our
  p-min 0.0 greedy path. Re-verify the greedy baseline (KLD null control + a
  fixed-prompt diff).
- CUDA flash-attention race/retune: #30103, #30573, #29803 (correctness races),
  #26289, #29435, #30168 (kernel selection / accumulation order). Can shift low
  bits of greedy logits with `-fa on`.
- **Negative result (method stated):** no q8_0-KV FA *semantic* change on CUDA in
  range — the only quantized-KV FA kernel work was SYCL (#31125) and Vulkan
  (#29639), not our backend. Our `-ctk/-ctv q8_0` path has only the general CUDA
  FA fixes above, no new semantics.

## Still open at b12019 (upgrade does NOT fix)

- **#29172** deep-KV CUDA decode+prefill collapse on a hybrid (~5.5× tg / ~21× pp
  at deep depth) — still open. Keep `CTX_SIZE` behavior in mind past ~150K.
- **#25618** MTP greedy output diverges from vanilla on a quantized target —
  still open. Our `draft-mtp` is not guaranteed greedy-lossless; the
  `docs/benchmarking.md` rule (never compare text across spec arms) stands.

## No requant required

#31028 ("merge tensors on convert", +7% TG / +5% PP) adds *optional* merged
tensors; the loader requests them `TENSOR_NOT_REQUIRED` and falls back to the
separate tensors, so our existing GGUF loads unchanged. Re-convert is optional,
only to capture that speedup.

## forge 0.9.5 → 0.10.0 (separate component)

13 of 14 build-time patches apply to 0.10.0 unchanged. The 14th,
`forge_stream_timeout.py`, no longer applies because **0.10.0 added
`_stream_with_timeout` with the identical `BackendError(408)` on
`httpx.ReadTimeout`** our patch supplied — upstream caught up. So the fix is to
DROP `forge_stream_timeout.py` from `Dockerfile.forge` and `test_forge_patches`,
not rebase it, then bump `FORGE_VERSION`. Do forge separately from llama.

## Verification — applied and checked 2026-10-31

Applied by bumping `LLAMA_TAG` to `server-cuda-b12019` and recreating only the
llama container (`compose up -d --no-deps --force-recreate llama`); forge,
capture and observe stayed up. b11118 image kept local for rollback.

- **Smoke: PASS.** Health ok; a tool-call turn returned a clean
  `get_weather({"city":"Paris"})` with `finish_reason: tool_calls` and reasoning
  preserved separately (the qwen3-coder parser changes #30557/#29876/#30088/#29942
  did not break tool extraction); a greedy turn returned exactly "UPGRADE OK".
  The server parsed every flag we pass and loaded, so nothing broke on the
  hybrid+MTP+spec config. Probes reach the stack from the container via
  `host.docker.internal:8080/8081`, not `127.0.0.1` (that is the container's own
  loopback, not the host's published port).
- **`cache_reuse is not supported by this context` is PRE-EXISTING, not a
  regression** — it is in the b11118 log and every earlier capacity log. It is a
  property of our hybrid + `kv_unified` context disabling the `--cache-reuse`
  tail-reuse feature, and is unrelated to the `--ctx-checkpoints` rollback that
  #26004 fixes.
- **#25618 is LIVE for us.** 8 fixed greedy prompts (temp 0), spec ON vs OFF on
  b12019: 6/8 byte-identical, 2 diverge (both long reasoning prompts). draft-mtp
  is not greedy-lossless on our Q4_K_M target. The benchmarking rule stands.
- **The engine changed greedy output.** b11118 spec-off vs b12019 spec-off: only
  1/8 identical. As the survey predicted (#29797 temp-0 greedy selection + CUDA FA
  retune), b12019 produces different greedy continuations — late, in reasoning,
  all plausible/correct. **This establishes output CHANGED, not that quality is
  preserved**; a token diff cannot grade better/worse.
